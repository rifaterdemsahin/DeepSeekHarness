🔌 Integrate with your existing harness & tools

Principle: reuse your instructions, tools and policies; don't rewrite them.

flowchart LR subgraph Yours[Your existing stack] A[AGENTS.md / CLAUDE.md]; B[.claude/skills]; C[MCP servers]; D[Shell hooks]; E[CI]; F[Editor] end subgraph CW[🐋 Codewhale] I[Instruction loader]; S[Skill discovery]; M[MCP client]; H[Hooks]; X[exec]; Z[ACP / Runtime API] end A --> I; B --> S; C --> M; D --> H; E --> X; F --> Z

1️⃣ Instructions: AGENTS.md just works

Codewhale reads AGENTS.md automatically. Other files load only if you opt in:

# ~/.codewhale/config.toml
project_instruction_imports = ["claude"]   # or "cursor","cline","windsurf","copilot","all"

2️⃣ Skills: your existing ones are discovered

Read-only compatible roots include .claude/skills, .agents/skills, .cursor/skills, .opencode/skills. Owned, writable roots are .codewhale/skills/ (project) and ~/.codewhale/skills/ (global). Workspace skills load only after /trust on --save. Use /skills manage to audit shadowing.

3️⃣ Tools: MCP both directions

  • Client: add servers via /mcp add (stdio or remote HTTP/SSE). Check with /mcp status / /mcp doctor.
  • Server: codewhale serve --mcp exposes its native tools to another client (write tools withheld unless you permit them).

4️⃣ Hooks: bolt on your own policy

[hooks]
enabled = true

[[hooks.hooks]]
name = "announce"
event = "session_start"
command = "echo 'Codewhale session started'"

tool_call_before with exit code 2 denies a tool call: a natural place for your company's rules. List events with /hooks events.

5️⃣ CI & editors

codewhale exec --hooks "Fix the failing tests"   # hooks opt-in for headless
codewhale review --pr 123                        # advisory PR review
codewhale serve --acp                            # Zed and other ACP editors
