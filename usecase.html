🎬 Real use case: "add a feature, prove it works"

This is the exact demo from the project README: a small Python repo with export.py and three tests. Task: add a --json flag. Codewhale edits, runs the tests, then a sub-agent reviews the result.

🪜 Step by step

1
Start clean. git status is clean, then run codewhale in the repo root.
2
Pick a model once. /provider (or F3), paste a key. DeepSeek is the default provider.
3
Say the goal.
Add a --json flag to export.py, add tests, run them,
then have a sub-agent review the change.
4
Watch the loop. It reads files, edits export.py (edits apply without asking by default), and asks before any non-read-only shell command: y once · a allow similar · n refuse.
5
Verify. Tests run (3 pass), a delegated review reports no issues, the task list shows three completed steps.
6
Audit or revert. /receipts lists files changed, commands run, approvals. Don't like it? /undo.

🔁 What actually happens inside

sequenceDiagram actor You participant H as 🐋 Harness participant M as 🧠 Model participant FS as 📁 Repo/Shell You->>H: task loop until done or needs you H->>M: context + tool list M-->>H: 'call tool: read export.py' H->>FS: run tool (policy + sandbox check) FS-->>H: result H->>H: log receipt end H->>M: spawn review sub-agent M-->>H: 'no issues' H-->>You: summary + diff + receipts

🤖 Same task, no human: CI

codewhale exec "Fix the failing tests and explain what changed."
⚠️ Read the headless docs before using --auto: it means Full Access unless you add a sandbox. Hooks are off in exec unless you pass --hooks.
